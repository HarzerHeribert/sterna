## what it is

A coding agent for your terminal. You give it a task in a project; it works the task in turns, the way Claude Code or Codex does. It is named for Sterna paradisaea, the Arctic tern, which makes the longest migration of any animal.

one program per turn

Instead of a round trip per tool, the model writes one TypeScript program each turn — a cell — that runs in a V8 isolate inside Sterna. read, grep, edit and bash are functions in it, so one turn can read, search, edit, run the tests and branch on the result.

results stay live

What a tool returns stays in the isolate as a named handle. The model sees a bounded preview and works on the handle in the next cell; a large grep costs a preview, not its bytes on every later turn.

a flock of helpers

Cheap models answer narrow questions from inside a cell without costing a turn: the scout finds where something lives, the reducer cuts a log to its failures, the checker tests a claim before a task is accepted. Subagents take a separable goal and run beside the task.

the longest run on the least

History only grows, so each request extends the last one and the provider's prompt cache holds. When the context stops fitting it is compacted while the isolate keeps running — a result from turn three is still there.

// cell 1 — everything the next step is about to change
const [limits, hits] = await Promise.all([

return {matched: hits.length};

const failures = await helper.reduce(run.stdout);
return {passed: run.exit_code === 0, failures};

## install and update

$ curl -fsSL https://harzerheribert.github.io/sterna/install.sh | sh

The installer picks this machine's archive from the newest release, verifies it against the release's SHA256SUMS, unpacks it into a fresh ~/.local/lib/sterna/versions/<tag> and links sterna and inference-gateway into ~/.local/bin. It installs nothing else, touches no credential and edits no shell profile.

macOS, Apple siliconinstaller
Linux x86_64, arm64installer
Windows x64, arm64.zip archives on the releases page; no installer yet

A release install checks for a newer release when a session starts and installs it beside the running one; the next start uses it. sterna update does it on demand, sterna update --check only asks.

## start

$ cd your-project
$ sterna

The first time, type /login to connect a subscription in the browser, store an API key or add your own endpoint; /models chooses the model and its effort. Sterna reads what the project already has: AGENTS.md and CLAUDE.md, commands and skills in .claude/, and the MCP servers in .mcp.json.

## accounts and models

Sterna talks to models through the inference gateway, a separate program it starts beside itself. The gateway holds your API keys and subscription logins — they never enter the conversation, the transcript or a log — pools several accounts of one kind, and translates between the Anthropic, OpenAI and Gemini wire formats. It picks the provider and account for a request and never changes the model or effort you chose.

$ inference-gateway subscriptions usage   # each subscription's limits, and when they reset
$ inference-gateway credentials set openai # store a key, read from stdin

Signing a subscription in to a third-party tool is against some providers' terms; Sterna shows each warning before it signs in.

## build from source

$ cargo build --release -p sterna -p inference-gateway
$ scripts/install-local.sh              # install into a new version directory
$ scripts/install-local.sh --rollback   # back to the previous version

Each binary is self-contained: no daemon, Node or Python. Sterna embeds V8, so its first build takes a while.
